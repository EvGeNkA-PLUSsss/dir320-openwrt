# Универсальная очистка системы

Очистка не привязана к модели роутера и не содержит списков «USB-пакетов»: она вычисляет неиспользуемое по фактическому состоянию системы.

## Как определяется «неиспользуемое»

### 1. Пакеты по графу зависимостей

- читаются все `/usr/lib/opkg/info/*.control`;
- собирается множество зависимостей всех установленных пакетов;
- «лист» — установленный пакет, от которого никто не зависит;
- для каждого листа считается **реальный объём в overlay** (сумма размеров файлов, принадлежащих пакету и лежащих в `/overlay/upper`), а не `Installed-Size` из репозитория. Пакеты, целиком лежащие в squashfs (ROM), показываются как `0 Б ROM` — удаление места не освободит.

### 2. Защита

Нельзя удалить:

- пакеты, владеющие **запущенными сейчас процессами** (по `/proc/<pid>/exe` → карта файл→пакет из `*.list`);
- пакеты, владеющие **включёнными службами** (`/etc/rc.d/S*` → init-скрипт → пакет);
- базовые имена пакетов (`base-files`, `busybox`, `libc`, `procd`, `ubus`, `uci`, `netifd`, `dnsmasq`, `dropbear`, `firewall`, `uhttpd`, `rpcd`, `vsftpd`, `lua`, `iwinfo`, `iw`, `swconfig` и т.п.);
- владельцы критичных файлов (интерпретатор Lua, `nixio`, веб-сервер, Dropbear, Netifd, DNSMasq, Wi-Fi-утилиты, `rpcd`);
- пакеты **загруженных модулей ядра** (по `/proc/modules`), чтобы не отвалилось железо;
- device-support модули (`kmod-leds*`, `kmod-input*`, `kmod-gpio*`, `kmod-button*`, `kmod-hwmon*`, `kmod-thermal*`);
- пакеты WAN-протоколов, если они реально используются в `/etc/config/network` (`ppp*` для PPPoE/PPTP/L2TP/3G, `odhcp*` для IPv6-туннелей);
- `luci*`, `rpcd*`, `liblucihttp*` — чтобы не сломать веб-интерфейсы;
- всё, от чего эти пакеты зависят.

### 3. Файлы без владельца

Сканируется `/overlay/upper`, вычитаются все файлы, принадлежащие пакетам. Кандидаты — файлы ≥ 4 КБ, кроме `/etc`, `/srv`, `/root`, базы opkg и файлов панели. Расширенный режим добавляет `/etc` (тогда кандидат помечается `SYS`).

### 4. Пустые каталоги

Отдельная команда удаляет пустые каталоги в overlay, оставшиеся от удалённых пакетов (кроме корневых системных вроде `/usr`, `/lib`, `/etc`).

## Режимы

| Режим | Что показывает | Подтверждение |
|---|---|---|
| обычный | листья без защиты + файлы без владельца | `yes` |
| экспертный (`e`) | то же + системные пакеты/файлы (`SYS`) | `YES` (заглавными) |

Экспертный режим может сломать систему — он для тех, кто понимает, что делает.

## Управление в интерфейсе

| Команда | Действие |
|---|---|
| цифра | включить/выключить элемент |
| `a` | выбрать все |
| `n` | снять все |
| `o` | только то, что реально освободит overlay |
| `i` | инвертировать выбор |
| `p` / Enter | следующая страница |
| `e` | экспертный режим |
| `z` | удалить пустые каталоги |
| `d` | удалить выбранное |
| `r` | пересчитать |
| `b` | назад |

## Неинтерактивно

```sh
sh dir320-tui.sh --detect
```

Выводит TSV:

```
package <name> <overlay_bytes> <installed_size> <description> <protected:0|1>
file    <path> <size>
```

Такой вывод удобно обрабатывать скриптами: `awk -F'\t' '$1=="package" && $5==0'` и т.п.

## Что удаляется через opkg

Для пакетов вызывается `opkg remove <список>` — одним вызовом, чтобы меньше нагружать память. Удаление файлов-сирот — прямой `rm` в `/overlay/upper` после проверки пути. После операции показывается, сколько освободилось.

## Ограничения

- Пакеты в ROM не освобождают место, но могут быть удалены (например, неиспользуемый `ppp`).
- Граф зависимостей строится по установленным пакетам; если конфиг ссылается на удаляемую программу (например, firewall-правило), это не отслеживается — проверяйте список глазами.
- Если места в RAM мало, детект может замедлиться: перед сканированием установщик сбрасывает кеш (`drop_caches`).
